# 埋点云端对接文档

## 1. 概述

本文档说明如何将埋点数据上传到云端，包括统一的数据格式规范、实现方案和使用示例。

---

## 2. 统一数据格式规范

### 2.1 JSON格式定义

所有埋点数据统一使用以下JSON格式：

```json
{
  "from": "vlago",
  "type": "trigger",
  "event": "事件名称",
  "timestamp": 1704067200000,
  "timestamp_str": "2024-01-01 12:00:00",
  "node_name": "SceneServices",
  "file": "src/scene/scene_services/src/scene_services.cpp",
  "line": 731,
  "function": "ChangeMode",
  "data": {
    "old_mode": "standard",
    "new_mode": "auxiliary"
  },
  "vehicle_id": "VLAGO_001",
  "version": "1.0.0"
}
```

### 2.2 字段说明

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `from` | string | 是 | 数据来源，固定值 "vlago" |
| `type` | string | 是 | 消息类型，固定值 "trigger" |
| `event` | string | 是 | 事件名称，如 "mode_switch_start" |
| `timestamp` | int64 | 是 | 时间戳(毫秒) |
| `timestamp_str` | string | 是 | 时间戳字符串 "YYYY-MM-DD HH:MM:SS" |
| `node_name` | string | 否 | ROS节点名称 |
| `file` | string | 否 | 源文件路径 |
| `line` | int | 否 | 源代码行号 |
| `function` | string | 否 | 函数名称 |
| `data` | object | 否 | 业务数据键值对 |
| `vehicle_id` | string | 否 | 车辆ID |
| `version` | string | 否 | 软件版本 |

### 2.3 事件类型定义

| 事件类型 | 前缀 | 示例 | 说明 |
|---------|------|------|------|
| 模式切换 | `mode_switch_` | `mode_switch_start`, `mode_switch_success` | 模式相关事件 |
| 碰撞检测 | `collision_` | `collision_check_start`, `collision_detected` | 碰撞检测相关 |
| 服务调用 | `service_` | `service_gears_request`, `service_gears_response` | 服务调用相关 |
| 传感器数据 | `sensor_` | `sensor_gps_data`, `sensor_imu_data` | 传感器数据相关 |
| 错误异常 | `error_` | `error_lx_camera`, `error_service_timeout` | 错误异常相关 |
| 定时器 | `timer_` | `timer_health_callback` | 定时器相关 |

## 3. 实现方案

### 3.1 架构设计

```
┌─────────────────┐
│   业务代码      │
│  (埋点调用)     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
```

#### 示例3: 服务调用埋点

```cpp
// 文件: src/control_service/src/control/gears_control.cpp
void GearsControl::handleGearsStart(
    const std::shared_ptr<interface::srv::GearsControls::Request> request,
    std::shared_ptr<interface::srv::GearsControls::Response> response) {
    
    // 埋点: 服务请求
    TRIGGER_LOG("service_gears_request", {
        {"gear", std::to_string(request->gear)},
        {"helpcar", std::to_string(request->helpcar)},
        {"sos", std::to_string(request->sos)}
    });
    
    auto futer = gears_control_client_->async_send_request(request);
    auto status = futer.wait_for(std::chrono::seconds(1));
    
    if (status == std::future_status::timeout) {
        // 埋点: 服务超时
        TRIGGER_LOG("error_service_timeout", {
            {"service_name", "gears_control"},
            {"timeout_seconds", "1"}
        });
        response->code = 0;
        return;
    }
    
    auto result = futer.get();
    
    // 埋点: 服务响应
    TRIGGER_LOG("service_gears_response", {
        {"result_code", std::to_string(result->code)},
        {"response_code", std::to_string(response->code)}
    });
    
    response->code = (result->code == 0) ? 0 : -1;
}
```

3. **实时监控**: 对关键事件进行实时告警
4. **数据分析**: 定期分析埋点数据，生成报表

## 6. 配置说明

### 6.1 编译配置

在 `CMakeLists.txt` 中添加：

```cmake
# 添加trigger_logger库
add_library(trigger_logger
    src/common/utils/trigger_logger.cpp
)

target_include_directories(trigger_logger PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

target_link_libraries(trigger_logger
    Boost::system
    Boost::thread
    Boost::chrono
)
```

### 6.2 运行时配置

可以通过ROS参数或配置文件设置：

```cpp
// 从ROS参数读取配置
this->declare_parameter("trigger.websocket_url", "ws://60.205.235.193:3009");
this->declare_parameter("trigger.vehicle_id", "");
this->declare_parameter("trigger.version", "1.0.0");

std::string ws_url = this->get_parameter("trigger.websocket_url").as_string();
std::string vehicle_id = this->get_parameter("trigger.vehicle_id").as_string();
std::string version = this->get_parameter("trigger.version").as_string();

utils::TriggerLogger::getInstance().initialize(ws_url, vehicle_id, version);
```

## 7. 性能优化

### 7.1 队列管理

- **队列大小限制**: 10000条（可配置）
- **队列满时**: 丢弃最旧的数据
- **异步上传**: 不阻塞业务逻辑

### 7.2 数据采样

对于高频触发点，建议进行采样：

```cpp
// 采样示例：每10次触发只记录1次
static int collision_check_count = 0;
if (++collision_check_count % 10 == 0) {
    TRIGGER_LOG("collision_check_result", {
        {"collision_detected", collision_detected ? "true" : "false"}
    });
}
```

### 7.3 批量上传

可以修改上传逻辑，支持批量上传：

```cpp
// 批量上传（每10条或每100ms）
std::vector<TriggerData> batch;
// ... 收集数据
if (batch.size() >= 10 || timeout) {
    sendBatch(batch);
}
```

## 9. 故障排查

### 9.1 常见问题

**问题1: 埋点数据未上传**

- 检查是否已初始化 `TriggerLogger`
- 检查WebSocket连接是否正常
- 检查队列是否已满

**问题2: 数据格式错误**

- 检查JSON格式是否正确
- 检查字符串转义是否正确
- 检查数据类型是否匹配

**问题3: 连接断开**

- 自动重连机制会在2秒后重试
- 检查网络连接
- 检查服务器是否正常运行

### 9.2 调试方法

## 10. 总结

1. **统一格式**: 所有埋点数据使用统一的JSON格式
2. **简单易用**: 提供便捷宏，一行代码完成埋点
3. **异步上传**: 不阻塞业务逻辑，性能影响最小
4. **自动重连**: 网络断开时自动重连
5. **队列管理**: 防止内存溢出，队列满时自动丢弃旧数据
