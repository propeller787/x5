# 共享控制辅助通行项目 ROS2 Humble 落地方案

## 1. 项目目标

本项目面向电动轮椅在窄门、窄通道、贴边转弯、倒退退出等不好操控场景下的辅助通行。系统不使用 Nav2，不做全局自主导航，不接管底盘驱动开发，只在现有摇杆控制链路上增加一层低速、局部、可降级的共享控制能力。

核心目标：

- 人通过摇杆输入意图，系统根据三水平雷达辅助修正方向、限制速度、避免刮碰。
- 在窄门场景下识别门洞、估计门中心线、计算左右剩余间隙，并辅助轮椅居中通过。
- 在任何辅助模式下保留人工优先权，用户松杆、反向操作、急停或取消辅助时，系统立即退出或停车。
- 输出到既有电机控制 topic：`/nav/control`，消息类型为 `geometry_msgs/msg/Twist`。

既有接口：

| Topic | 类型 | 方向 | 说明 |
|---|---|---|---|
| `/handle/control` | `geometry_msgs/msg/Twist` | 输入 | 摇杆控制指令 |
| `/nav/control` | `geometry_msgs/msg/Twist` | 输出 | 发送给电机控制的最终速度指令 |
| `/wheel/twist` | `geometry_msgs/msg/TwistStamped` | 输入 | 带时间戳的车辆速度信息，用于里程计和定位 |

## 2. 总体技术路线

系统采用“感知融合 + 局部几何识别 + 共享控制 + 安全监控”的轻量架构。

```text
三水平雷达
  ↓
TF 外参标定与坐标统一
  ↓
局部栅格 / 障碍物距离 / 安全区域计算
  ↓
门洞识别 / 门中心线 / 左右间隙估计
  ↓
窄门状态机
  ↓
共享控制器：摇杆意图 + 自动角速度修正 + 限速
  ↓
碰撞监控：减速 / 停车 / 后部保护
  ↓
/nav/control
```

不使用 Nav2 的原因：

- 当前场景是低速局部辅助通行，不需要全局规划、全局地图和行为树。
- 三雷达辅助过门更依赖局部门框几何、间隙估计和人工意图融合。
- 自研轻量链路更容易满足载人轮椅的安全降级、人工优先和工程调参需求。

## 3. 坐标系与 TF 设计

推荐坐标系：

```text
odom
  └── base_link
        ├── laser_front_left
        ├── laser_front_right
        └── laser_rear
```

坐标约定：

- `base_link`：轮椅底盘中心，建议放在驱动轮轴线中心或几何中心，x 轴向前，y 轴向左，z 轴向上。
- `laser_front_left`：前左水平雷达坐标系。
- `laser_front_right`：前右水平雷达坐标系。
- `laser_rear`：后部水平雷达坐标系。
- `odom`：由 `/wheel/twist` 积分得到的里程计坐标系，仅用于短时间运动补偿和日志分析。

三雷达外参需要在 URDF 或静态 TF 中配置：

```yaml
front_left_laser:
  parent: base_link
  child: laser_front_left
  xyz: [0.42, 0.28, 0.18]
  rpy: [0.0, 0.0, 0.0]

front_right_laser:
  parent: base_link
  child: laser_front_right
  xyz: [0.42, -0.28, 0.18]
  rpy: [0.0, 0.0, 0.0]

rear_laser:
  parent: base_link
  child: laser_rear
  xyz: [-0.42, 0.0, 0.18]
  rpy: [0.0, 0.0, 3.14159]
```

实际数值必须根据安装位置测量。调试阶段需要在 RViz 中检查：

- 三个雷达扫描是否都落在正确方向。
- 前方墙面是否在 `base_link` 前方。
- 后雷达是否正确覆盖车尾区域。
- 左右雷达点云在同一堵墙上是否重合，无明显错位。

## 7. 三雷达融合方案

### 7.1 输入处理

`lidar_fusion_node` 订阅三个 `LaserScan`，每帧处理：

1. 检查时间戳是否过期。
2. 按 `range_min`、`range_max` 过滤无效点。
3. 去除 NaN、Inf。
4. 通过 TF2 转换到 `base_link`。
5. 合并为统一 `PointCloud2`。
6. 发布 `/assist/points`。

建议参数：

```yaml
lidar_fusion:
  scan_timeout: 0.20
  min_range: 0.05
  max_range: 4.00
  point_downsample_resolution: 0.02
  publish_rate: 20.0
```

### 7.2 运动补偿

MVP 阶段可不做复杂运动补偿，因为轮椅过门速度很低。建议限制辅助速度：

- 普通辅助最大速度：`0.35 m/s`
- 窄门辅助最大速度：`0.15 m/s`
- 对齐阶段最大速度：`0.08 m/s`

如果后续雷达时间戳差异明显，可基于 `/wheel/twist` 对点云做短时间运动补偿。

## 8. 局部栅格方案

`local_grid_node` 将融合点云投影到 `base_link` 下的局部占据栅格。

推荐局部地图范围：

```yaml
local_grid:
  frame_id: base_link
  resolution: 0.03
  x_min: -1.20
  x_max: 2.20
  y_min: -1.20
  y_max: 1.20
  obstacle_inflation: 0.08
  decay_time: 0.30
```

说明：

- 前方 2.2 m 足够识别门和控制低速通过。
- 后方 1.2 m 用于后退保护和尾部过门判断。
- 左右各 1.2 m 覆盖普通室内门、走廊、贴边场景。
- 栅格分辨率 3 cm，能兼顾门框识别精度和 CPU 负载。

处理流程：

```text
PointCloud2
  ↓
过滤车体 footprint 内部点
  ↓
投影到 2D 栅格
  ↓
障碍膨胀
  ↓
时间衰减
  ↓
发布 OccupancyGrid
```

车体 footprint 建议用多边形而不是矩形：

```yaml
footprint:
  points:
    - [ 0.48,  0.34]
    - [ 0.48, -0.34]
    - [-0.48, -0.34]
    - [-0.48,  0.34]
```

实际轮椅宽度、长度和雷达盲区需要现场测量后更新。

## 9. 障碍物距离与碰撞区

### 9.1 分区

基于 footprint 外扩得到多个安全区域：

```text
前方停车区       x ∈ [front_edge, front_edge + stop_distance]
前方减速区       x ∈ [front_edge, front_edge + slow_distance]
左侧停车区       y ∈ [left_edge, left_edge + side_stop]
右侧停车区       y ∈ [right_edge - side_stop, right_edge]
后方停车区       x ∈ [rear_edge - stop_distance, rear_edge]
```

建议参数：

```yaml
obstacle_distance:
  front_stop_distance: 0.18
  front_slow_distance: 0.60
  rear_stop_distance: 0.16
  rear_slow_distance: 0.45
  side_stop_distance: 0.06
  side_slow_distance: 0.18
  min_valid_points_for_stop: 3
```

### 9.2 输出距离

每一帧从局部栅格或点云中计算：

- 前方最近障碍距离。
- 后方最近障碍距离。
- 左右侧最近障碍距离。
- 前左、前右、后左、后右四个角区域最近距离。
- 当前是否触发减速或停车。

### 9.3 限速曲线

推荐使用连续限速而不是硬切换：

```text
若 d <= stop_distance:
  v_max = 0
若 stop_distance < d < slow_distance:
  v_max = v_nominal * (d - stop_distance) / (slow_distance - stop_distance)
若 d >= slow_distance:
  v_max = v_nominal
```

转向限速：

```text
左侧距离过小且 omega > 0，限制左转
右侧距离过小且 omega < 0，限制右转
后方距离过小且 v < 0，限制倒车
```

## 10. 门洞识别方案

`door_detector_node` 订阅 `/assist/local_grid` 和 `/assist/points`，输出 `/assist/door_candidate`。

### 10.1 检测区域

仅在前方 ROI 中检测门：

```yaml
door_detector:
  roi_x_min: 0.25
  roi_x_max: 2.00
  roi_y_min: -0.90
  roi_y_max: 0.90
  min_door_width: 0.72
  max_door_width: 1.20
  wheelchair_width: 0.68
  required_side_margin: 0.05
```

如果轮椅实际宽度是 0.62 m，则最小可通行门宽建议：

```text
min_passable_width = wheelchair_width + 2 * required_side_margin
                   = 0.62 + 2 * 0.05
                   = 0.72 m
```

### 10.2 三种识别方式

#### 方式 A：左右门框点识别

适用于门框明显、门边有立柱的场景。

流程：

1. 在前方 ROI 中提取障碍点。
2. 聚类得到左右边界点簇。
3. 找到 y 方向上相对成对的边界。
4. 计算门洞宽度和中心。
5. 连续多帧稳定后输出高置信度。

#### 方式 B：平行墙面识别

适用于窄通道或门洞两侧连接墙面的场景。

流程：

1. 对 ROI 点云做线段拟合。
2. 找到左右两条近似平行线。
3. 计算两线之间距离作为通道宽度。
4. 中线作为通行中心线。

#### 方式 C：最大自由间隙识别

适用于门框不完整、只有局部边界的场景，是降级方案。

流程：

1. 在前方多个 x 截面扫描 y 方向空闲区间。
2. 找到最大连续可通行空隙。
3. 选择最接近摇杆方向的自由空隙。
4. 输出较低置信度门候选。

### 10.3 稳定性判断

门候选必须满足：

- 连续 `N=3~5` 帧检测到。
- 门宽变化小于 `0.08 m`。
- 中心线横向变化小于 `0.06 m`。
- 角度变化小于 `8 deg`。
- 门宽大于车宽加安全余量。

置信度建议：

```text
confidence = w1 * width_score
           + w2 * symmetry_score
           + w3 * temporal_score
           + w4 * line_fit_score
```

MVP 可先简化为规则分数：

- 宽度合法：`+0.3`
- 左右边界都存在：`+0.3`
- 连续稳定：`+0.2`
- 中心线角度合理：`+0.2`

当 `confidence >= 0.65` 时允许进入窄门辅助。

## 11. 门中心线与左右间隙估计

门中心线在 `base_link` 坐标系下表示为：

```text
center_x, center_y, yaw
```

其中：

- `center_x`：门中心点前向距离。
- `center_y`：门中心点横向偏移，左正右负。
- `yaw`：门方向相对车体 x 轴角度。

控制误差：

```text
lateral_error = center_y
angle_error = normalize(yaw)
```

左右间隙估计：

```text
left_clearance  = left_boundary_y - wheelchair_half_width
right_clearance = -right_boundary_y - wheelchair_half_width
min_clearance   = min(left_clearance, right_clearance)
```

如果门不是正对车体，需要将车体 footprint 沿候选中心线方向投影，计算左右最近距离。MVP 阶段可在低速和小角度范围内先用横向近似；当 `abs(angle_error) > 15 deg` 时不进入自动过门，只进入对齐提示/限速。

## 12. 窄门状态机

### 12.1 状态定义

```text
IDLE
  ↓ 检测到门候选，且用户向前推动摇杆
SEARCH
  ↓ 门候选稳定
APPROACH
  ↓ 距离进入对齐范围
ALIGN
  ↓ 横向误差和角度误差满足阈值
ENTER
  ↓ 车头进入门洞
PASSING
  ↓ 后部接近门洞，通过后雷达保护
EXIT
  ↓ 后部脱离门洞
COMPLETE
  ↓
IDLE
```

异常退出：

```text
任意状态
  ↓ 用户松杆 / 反向强操作 / 门候选丢失过久 / 安全停车触发
ABORT
  ↓
IDLE 或 MANUAL_ONLY
```

### 12.2 状态切换条件

| 当前状态 | 进入条件 | 退出条件 | 控制策略 |
|---|---|---|---|
| `IDLE` | 默认状态 | 用户前进且检测到疑似门 | 仅普通避障限速 |
| `SEARCH` | 存在门候选 | 候选稳定或超时 | 限速，轻微方向修正 |
| `APPROACH` | 门可信度高 | 距离门中心 `< 0.8 m` | 向中心线靠近，速度限制 |
| `ALIGN` | 接近门洞 | 横向误差 `< 0.04 m` 且角度误差 `< 5 deg` | 低速对齐，角速度修正增强 |
| `ENTER` | 对齐完成 | 车头进入门洞 | 前方与侧方强保护 |
| `PASSING` | 车体进入门洞 | 后部通过门框 | 以后雷达和左右间隙保护为主 |
| `EXIT` | 后部接近出口 | 后方/侧方风险解除 | 逐步释放辅助 |
| `COMPLETE` | 完成 | 0.5 s 后回到 `IDLE` | 恢复普通辅助 |
| `ABORT` | 异常或用户取消 | 停稳或人工接管 | 降速停车或直接人工 |

### 12.3 状态机参数

```yaml
narrow_door_state_machine:
  door_detect_confidence_enter: 0.65
  door_detect_confidence_keep: 0.45
  candidate_lost_timeout: 0.40
  user_forward_threshold: 0.03
  user_cancel_angular_threshold: 0.60
  approach_distance: 1.20
  align_distance: 0.80
  enter_distance: 0.35
  lateral_error_enter: 0.04
  angle_error_enter_deg: 5.0
  complete_hold_time: 0.50
```

## 13. 共享控制器设计

### 13.1 控制原则

共享控制器不是直接替代用户输入，而是对摇杆输入做安全增强：

- 保留用户线速度意图。
- 系统主要修正角速度。
- 在窄门状态下限制最大线速度和最大角速度。
- 当左右间隙不均时，角速度向间隙更大的方向微调。
- 用户强烈反向操作时，退出辅助。

### 13.2 输入输出

输入：

- `/handle/control`
- `/wheel/twist`
- `/assist/door_candidate`
- `/assist/obstacle_distance`

输出：

- `/assist/control_raw`
- `/assist/state`

最终 `/nav/control` 由 `safety_guard_node` 发布。

### 13.3 摇杆融合公式

用户输入：

```text
v_user = handle.linear.x
w_user = handle.angular.z
```

普通辅助模式：

```text
v_cmd = clamp(v_user, -v_manual_max, v_manual_max)
w_cmd = clamp(w_user, -w_manual_max, w_manual_max)
```

窄门辅助模式：

```text
v_cmd = clamp(v_user, 0, v_door_max)

w_assist = k_y * lateral_error
         + k_theta * angle_error
         + k_gap * (right_clearance - left_clearance)

w_cmd = blend_ratio * w_assist + (1 - blend_ratio) * w_user
w_cmd = clamp(w_cmd, -w_door_max, w_door_max)
```

说明：

- 当 `center_y > 0`，门中心在左侧，系统应适当左转。
- 当 `left_clearance < right_clearance`，左侧更危险，系统应适当向右修正。
- `k_gap` 符号要通过实车测试确认，建议在 RViz 和低速空载测试中调参。

推荐初始参数：

```yaml
shared_controller:
  manual_v_max: 0.45
  manual_w_max: 1.00

  obstacle_assist_v_max: 0.35
  obstacle_assist_w_max: 0.80

  door_v_max: 0.15
  door_align_v_max: 0.08
  door_w_max: 0.45

  k_lateral: 1.20
  k_angle: 1.00
  k_gap: 0.80
  blend_ratio_approach: 0.50
  blend_ratio_align: 0.80
  blend_ratio_passing: 0.70

  max_accel_linear: 0.25
  max_accel_angular: 0.80
```

### 13.4 速度平滑

为了避免轮椅顿挫，输出前做加速度限制：

```text
v_out = limit_rate(v_cmd, v_prev, max_accel_linear, dt)
w_out = limit_rate(w_cmd, w_prev, max_accel_angular, dt)
```

建议控制频率：

```yaml
control_rate: 50.0
command_timeout: 0.20
```

如果 `/handle/control` 超过 `0.20 s` 未更新，应输出零速度。

## 14. 碰撞监控与限速停车

`safety_guard_node` 是最后一道 ROS2 软件安全层，必须只订阅候选速度，发布最终 `/nav/control`。

输入：

- `/assist/control_raw`
- `/assist/obstacle_distance`
- `/assist/local_grid`
- `/wheel/twist`

输出：

- `/nav/control`
- `/assist/state` 中的 `safety_limited`、`emergency_stop` 字段可由共享控制器或安全节点合并发布，工程上建议安全节点另发 `/assist/safety_status`。

### 14.1 安全裁剪规则

前进：

```text
if v_cmd > 0 and front_stop:
  v_safe = 0
else if v_cmd > 0:
  v_safe = min(v_cmd, front_v_limit)
```

倒退：

```text
if v_cmd < 0 and rear_stop:
  v_safe = 0
else if v_cmd < 0:
  v_safe = max(v_cmd, -rear_v_limit)
```

转向：

```text
if omega_cmd > 0 and left side too close:
  omega_safe = min(omega_cmd, left_turn_limit)

if omega_cmd < 0 and right side too close:
  omega_safe = max(omega_cmd, -right_turn_limit)
```

角点保护：

- 前左角过近时，限制前进和左转。
- 前右角过近时，限制前进和右转。
- 后左角过近时，限制倒退和右转倒车。
- 后右角过近时，限制倒退和左转倒车。

### 14.2 软件急停条件

触发任一条件时输出零速度：

- 前方停车区存在障碍，且当前命令为前进。
- 后方停车区存在障碍，且当前命令为倒退。
- 左右侧停车区距离小于硬阈值，且命令继续向危险方向转动。
- 雷达数据超时。
- TF 变换失败超过阈值。
- `/handle/control` 超时。
- 内部节点心跳超时。

建议参数：

```yaml
safety_guard:
  publish_rate: 50.0
  cmd_timeout: 0.20
  lidar_timeout: 0.30
  tf_fail_timeout: 0.50
  emergency_stop_hold_time: 0.30

  min_front_stop: 0.18
  min_rear_stop: 0.16
  min_side_stop: 0.05

  slow_zone_front: 0.60
  slow_zone_rear: 0.45
  slow_zone_side: 0.18
```

## 15. 模式管理

MVP 可以不增加 UI topic，自动进入辅助：

- 默认处于 `OBSTACLE_ASSIST`，对所有摇杆命令做限速避碰。
- 当检测到门候选、用户持续向前推动摇杆、门宽满足条件时，进入 `NARROW_DOOR_ASSIST`。
- 当门候选消失或通过完成，回到 `OBSTACLE_ASSIST`。

产品化阶段建议增加模式 topic：

| Topic | 类型 | 说明 |
|---|---|---|
| `/assist/enable` | `std_msgs/msg/Bool` | 开关辅助 |
| `/assist/mode_request` | `std_msgs/msg/UInt8` | 手动请求普通辅助/窄门辅助 |
| `/assist/cancel` | `std_msgs/msg/Empty` | 取消当前辅助 |

人工优先级：

```text
硬件急停 > 手动取消 > 摇杆反向强操作 > 安全停车 > 窄门辅助 > 普通避障辅助
```

## 16. 里程计与 `/wheel/twist` 使用

`/wheel/twist` 不直接参与底盘控制，但用于：

- 判断轮椅是否真的在移动。
- 辅助状态机判断是否通过门洞。
- 控制日志记录。
- 后续扩展为短时里程计 `odom -> base_link`。

最小实现：

```text
/wheel/twist
  ↓
integrate vx, wz
  ↓
publish nav_msgs/Odometry /wheel/odom
  ↓
publish odom -> base_link TF
```

注意：

- 如果已有定位系统发布 `odom -> base_link`，本项目不要重复发布同一 TF。
- 如果没有定位系统，可以在 `wheelchair_lidar_fusion` 或单独 `wheelchair_odometry` 包中根据 `/wheel/twist` 发布短时 odom。
- 过门辅助核心计算仍以 `base_link` 局部坐标为主，不依赖长期精确定位。

## 19. 参数调试步骤

### 19.1 静态标定

1. 将轮椅放在空旷区域。
2. 启动三雷达和 TF。
3. 在 RViz 中确认扫描方向。
4. 靠近一面平整墙，观察前左/前右雷达点是否在同一直线。
5. 修正 `xyz/rpy`，直到墙面点重合。

### 19.2 局部栅格调试

1. 用纸箱或门框模拟障碍。
2. 检查栅格中障碍是否位置正确。
3. 调整 `resolution`、`obstacle_inflation`、`decay_time`。
4. 确认车体自身不会被误认为障碍。

### 19.3 安全区调试

1. 空载低速前进靠近墙面。
2. 验证前方减速区是否平滑降速。
3. 验证停车区是否输出 `v=0`。
4. 倒车靠近障碍，验证后雷达停车。
5. 左右贴边，验证转向限制。

### 19.4 门洞识别调试

1. 从 900 mm 门宽开始。
2. 再测试 800 mm、760 mm、720 mm。
3. 记录门候选中心、宽度、置信度。
4. 调整 `min_door_width`、`required_side_margin`、稳定帧数。

### 19.5 共享控制调试

1. 先只启用限速，不启用角速度修正。
2. 再启用小比例 `blend_ratio=0.3`。
3. 观察是否有左右摆动。
4. 逐步调大 `k_lateral` 和 `k_angle`。
5. 最后加入 `k_gap`，解决偏向一侧刮碰的问题。

## 22. 安全边界与硬件建议

软件辅助不能替代硬件安全。载人轮椅建议至少具备：

- 硬件急停按钮。
- 电机控制器 watchdog。
- 驱动器使能链路。
- 机械防撞边或低位触边。
- 雷达失效时默认停车。
- 低速辅助模式物理限速。

水平雷达局限：

- 可能看不到玻璃。
- 可能看不到低矮门槛。
- 可能漏检悬空障碍。
- 可能受强光、反光、黑色材质影响。

因此窄门辅助第一版建议限定为：

- 室内普通门。
- 门洞两侧可被雷达稳定检测。
- 地面平整。
- 低速空载验证后再载人验证。

## 25. 关键实现伪代码

### 25.1 共享控制主循环

```cpp
void SharedController::update()
{
  Twist user = latest_handle_cmd_;

  if (handle_timeout_) {
    publishZero();
    return;
  }

  updateDoorStateMachine();

  Twist raw;
  if (mode_ == NARROW_DOOR_ASSIST) {
    raw = computeDoorAssist(user, latest_door_, latest_distance_);
  } else {
    raw = computeObstacleAssist(user, latest_distance_);
  }

  raw = applyAccelerationLimit(raw);
  publish(raw);
}
```

### 25.2 窄门辅助控制

```cpp
Twist SharedController::computeDoorAssist(
  const Twist& user,
  const DoorCandidate& door,
  const ObstacleDistance& dist)
{
  Twist cmd;

  double v_max = state_ == ALIGN ? door_align_v_max_ : door_v_max_;
  cmd.linear.x = clamp(user.linear.x, 0.0, v_max);

  double w_assist =
      k_lateral_ * door.lateral_error +
      k_angle_ * door.angle_error +
      k_gap_ * (door.right_clearance - door.left_clearance);

  double blend = getBlendRatio(state_);
  cmd.angular.z = blend * w_assist + (1.0 - blend) * user.angular.z;
  cmd.angular.z = clamp(cmd.angular.z, -door_w_max_, door_w_max_);

  return cmd;
}
```

### 25.3 安全节点主循环

```cpp
void SafetyGuard::update()
{
  Twist cmd = latest_raw_cmd_;

  if (cmd_timeout_ || lidar_timeout_ || tf_failed_) {
    publishZeroToNavControl();
    return;
  }

  Twist safe = cmd;
  safe.linear.x = limitLinearByObstacle(cmd.linear.x, latest_distance_);
  safe.angular.z = limitAngularBySideDistance(cmd.angular.z, latest_distance_);

  if (shouldEmergencyStop(cmd, latest_distance_)) {
    safe.linear.x = 0.0;
    safe.angular.z = 0.0;
  }

  nav_control_pub_->publish(safe);
}
```

## 28. 结论

在 ROS2 Humble 下，不使用 Nav2 完全可以落地该项目。推荐按“局部辅助通行”而不是“自主导航”设计，通过三雷达构建局部环境理解，再用共享控制器修正摇杆命令，最后由安全节点统一限速和停车。

这个方案的工程重点不是复杂规划，而是：

- 雷达 TF 和局部栅格要可靠。
- 碰撞监控必须在最终输出前生效。
- 门洞识别要有置信度和降级策略。
- 共享控制必须尊重用户输入。
- 实地测试要覆盖门宽、角度、偏移和异常场景。
