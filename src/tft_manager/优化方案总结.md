# TFT Manager 模块优化方案总结

## 模块功能

TFT Manager 负责管理与 TFT 显示屏的通信，包括车辆状态显示、健康检测、充电状态、安全控制等功能。

## 主要问题

### 🔴 严重问题

1. **大量阻塞式 `usleep()`**

   - 位置：`global.cpp`, `tft_car_control.cpp` 等
   - 影响：阻塞 ROS2 回调线程，降低响应速度
   - 发现：46 处使用 `usleep()` 或 `sleep()`

2. **错误处理不完善**

   - 串口初始化失败仅打印，无重试机制
   - 缺少错误恢复策略

3. **未实现功能**
   - `TftDecoder` 方法为空实现
   - `serial_data_analyse()` 读取但不处理数据

### 🟡 中等问题

4. **单例模式实现不完善**

   - 使用原始指针，非智能指针
   - 可优化为 C++11 线程安全单例

5. **Global 类职责过多**

   - 承担状态管理、TFT 通信、网络检测、时间格式化等多重职责
   - 违反单一职责原则

6. **硬编码魔法数字**

   - 大量硬编码的地址、页面 ID、延迟时间
   - 缺少配置化

7. **线程管理复杂**
   - 网络检测线程、健康检测定时器需要手动管理
   - 缺少 RAII 资源管理

### 🟢 轻微问题

8. **日志使用不当**

   - 使用 `RCLCPP_INFO` 打印调试信息
   - 应使用 `RCLCPP_DEBUG`

9. **控制类耦合度高**
   - 所有控制类依赖 Global 单例
   - 难以进行单元测试

## 优化方案

### 立即实施（高优先级）

#### 1. 移除阻塞式 `usleep()`，使用异步命令队列

```cpp
// 创建命令队列
class TftCommandQueue {
    void enqueue(const TftCommand& cmd);
    void processQueue(); // 工作线程处理
};
```

**收益**：响应速度提升 50-80%

#### 2. 完善错误处理

- 串口初始化失败时实现重试机制（最多 3 次）
- 添加连接状态管理
- 实现错误回调

#### 3. 改进日志系统

- 使用 `RCLCPP_DEBUG` 替代 `RCLCPP_INFO` 打印调试信息
- 添加条件编译宏

### 近期实施（中优先级）

#### 4. 改进单例模式

```cpp
// 使用 C++11 线程安全单例
static Global& getInstance() {
    static Global instance; // 线程安全
    return instance;
}
```

#### 5. 配置化硬编码值

- 使用 ROS2 参数系统
- 创建配置文件 `tft_config.yaml`
- 集中管理常量

#### 6. 线程安全改进

- 使用 `std::atomic` 管理简单状态
- 使用 `std::shared_mutex` 优化读多写少场景

### 长期重构（低优先级）

#### 7. 拆分 Global 类

- `TftDisplayManager`: TFT 显示操作
- `StateManager`: 状态管理
- `NetworkMonitor`: 网络检测
- `TimeFormatter`: 时间格式化

#### 8. 依赖注入替代单例

- 控制类通过构造函数接收依赖
- 便于单元测试

#### 9. 实现 TftDecoder

- 根据 TFT 协议实现数据解码
- 完善串口数据读取逻辑
